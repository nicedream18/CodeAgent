# 上下文预算与治理完善计划

本文根据 2026-10-15 的代码整理，保留实施前的基线与设计。

实施状态：已完成本计划的功能实现、自动化验证及真实模型实验。具体证据、复现命令和使用边界见 [实现与验收](context-governance-acceptance.md)；下文的“当前基础”指实施前状态，建议值与步骤保留用于学习和追溯。

目标：工具结果进入模型前有明确上限；每次模型请求都留足生成空间；自动与手动压缩能保留继续执行所需的信息；CLI、TUI 和 trace 能解释发生了什么；压缩后仍能完成任务验收。

## 1. 当前基础和待补缺口

| 项目 | 当前基础 | 待补内容 |
| --- | --- | --- |
| token 估算 | `graph/nodes.py` 的 `estimate_context_tokens` 优先调用模型计数器，失败后按字符数估算 | 对实际发送的 messages、系统提示和工具 schema 计数；标记估算方式与不确定性 |
| 预算预留 | `context_monitor_node` 从配置窗口扣减预留量，预留最多为窗口的 20% | 统一窗口、输出上限、安全余量和压缩水位；消除静默压低输出预留的行为 |
| 工具裁剪 | `tools/execution.py` 的 `_truncate_result` 递归裁剪长字符串 | 增加整个结果、集合数量、嵌套深度和遍历量限制；覆盖异常返回 |
| Bash 输出 | stdout/stderr 默认各保留 6000 字符，长输出落盘 | 纳入统一结果预算，保留日志位置及裁剪原因 |
| 自动压缩 | 图节点之间检查，删除旧消息，写入 `HISTORY_SUMMARY.md` | 工具循环内调用前检查；压缩输入、输出也有预算；压缩后复核 |
| 关键记忆 | 图状态、分层记忆、压缩提示保留任务、TODO、验收标准与来源 | 建立机器校验的保留契约；限制 prompt 投影；处理后台任务及多轮摘要 |
| 手动 compact | CLI 和 TUI 压缩磁盘中的会话历史 | 共享压缩契约；支持对活动任务提交请求，在执行边界应用 |
| TUI 展示 | 自动压缩事件可显示前后估算量 | 显示生效范围、原因、估算方式、预留量及完成/失败状态 |
| 测试 | 已有预算、字段裁剪、压缩消息删除、会话 compact 等单元测试 | 增加请求边界、复杂结果、消息协议、并发及真实任务验收 |

上一轮核查运行了相关测试，结果为 15 passed；长文件与大命令输出能触发裁剪。1000 个各 100 字符的列表项仍返回约 10.4 万字符，说明字段限长不能代替结果总量限制。现有自动压缩测试使用模拟摘要与计数，不能作为真实模型续作通过的证据。

## 2. 完成后必须成立的约束

1. 每次发给模型的请求都经过预算检查，包括 planner、verifier、searchAgent、codeAgent、聊天/路由及摘要模型；不同调用可以使用不同的保留策略。
2. 任何进入 ToolMessage 的结果都经过统一大小控制。成功、失败、异常、MCP、子 Agent 查询等路径执行同一约束。
3. 压缩只能在模型请求和工具调用的边界进行；有一批并行或连续工具调用时，先完成对应结果，再改写消息历史。
4. 不删除必须保留的执行规则、当前任务、最新用户修正、验收标准、验证命令和未完成项。历史推断不能覆盖结构化当前状态。
5. 工具调用 ID 与结果配对保持有效；不会因裁剪或压缩重复执行已经完成的写文件、命令或其他有副作用的操作。
6. 压缩完成后的下一次请求确实使用新上下文；UI 不把“请求已接收”显示成“压缩已完成”。
7. 压缩仍无法满足预算时，返回明确原因并保留恢复信息，不递归压缩、无限重试或发送已知超限请求。
8. 完整历史、完整来源与工具产物可以保存在磁盘，但它们投影到后续 prompt 的内容必须有界。

## 3. 阶段一：统一预算模型与配置（P0）

学习重点：上下文窗口、输入 token、输出 token、安全余量、水位阈值和估算误差之间的关系。

### 具体改动

- 建议新增 `core/context_budget.py`，集中定义 `ContextBudget` 和 `BudgetSnapshot`，替代散落的阈值计算。
- 统一使用以下量：窗口容量 W、最大输出预留 R、安全余量 S、输入估算 I；可用输入预算 B = W - R - S。
- 当 I + R + S > W 时不得发送请求。提前压缩水位建议为 B 的 85%，压缩后的目标建议为 B 的 60%，避免刚压缩就再次触发。
- 上述比例是建议初始值。要求 `0 < target_ratio < high_ratio <= 1`，并在实验后调整；不是模型厂商的固定限制。
- `MOKIO_CONTEXT_TOKEN_LIMIT` 继续作为显式窗口配置；若增加模型能力表，仅使用可核实的模型信息。自定义兼容端点依赖明确配置，不推测其窗口。
- 保留现有 `MOKIO_MODEL_CONTEXT_RESERVE_TOKENS`，增加安全余量和水位配置。窗口小于输出预留、安全余量与必要提示之和时明确报错，不静默把预留削成 20%。
- `providers/openai_provider.py` 将输出预留落实为适合当前模型/端点的生成上限；参数不受支持时明确诊断，不静默丢弃生成约束。
- 统计实际请求内容：系统提示、当前任务、记忆投影、消息、工具调用参数和工具 schema。能精确计数时使用对应计数器；回退估算采用保守策略，并标为 estimated。
- 实际 API usage 可用于比较误差和调节余量，不能替代发送前的估算。尤其检查中文、长代码、JSON 和多字节文本。

### 验收

- 阈值前一 token、等于阈值、超过阈值行为明确。
- 非法配置、小窗口、未知模型和计数器失败有确定结果。
- spy 模型收到的每次请求满足配置的输入与输出预算，并带有生成上限。

## 4. 阶段二：把工具结果裁剪改成总量约束（P0）

学习重点：局部上限与整体上限、结构化数据裁剪、渐进读取和完整输出落盘。

### 具体改动

- 保留默认 12000 字符的单字段限制；建议增加整个序列化结果 24000 字符、列表最多 100 项、最大嵌套深度 8、最多访问 1000 个节点的初始限制。
- 以上限制需一起工作；整份结果的最终序列化长度包含元数据和截断标记。字符预算和 token 预算分开，前者不能代替请求级检查。
- 集中实现 `bound_tool_result`，在所有结果出口应用，包括工具抛出的长异常、参数错误、权限拒绝、超时及 runner 返回值。
- 保留状态、错误类别、工具名、任务 ID、调用 ID、路径引用等必要字段；对不可信超长元数据也设限制。无法维持原结构时返回约定的有界结果封装，不能直接切断 JSON。
- FileReadTool 优先保留行号、已展示范围和后续读取方式；超长单行需标记行内省略。修正“底层完整读过文件”和“模型看到了完整内容”的状态表达。
- Bash 输出在预算允许时保留开头与结尾，让最后的报错可见；完整内容沿用日志文件，保留 `stdout_path`、`stderr_path`。
- Grep、搜索结果和 MCP 结果限制条目数；保留来源 URL 或稳定引用，按需读取正文。
- 子 Agent 状态与结果查询使用同一总量控制。原始结果可独立保存，父 Agent 获取有界摘要和引用。
- 完整结果引用使用稳定 ID 或工作区相对路径；大产物不写进摘要、不在每次调用时重复注入。提供数量/磁盘清理策略，避免将 prompt 增长转移为重复产物增长。
- 统一裁剪元数据：原因、原始/保留大小、遗漏条目数、引用和继续读取参数；未知数量标为未知，不编造精确数。

### 验收

- 20 万字符文本、1000 个短条目、深层对象、长异常、超大 MCP 返回值均满足最终结果上限。
- 截断后 JSON 可解析，状态和任务引用有效，UTF-8 文本正常。
- 可按范围读取被省略的目标内容；读取补充片段仍受同样限制。
- 同一结果重复处理不重复追加截断标记、不重复生成完整输出副本。

## 5. 阶段三：让压缩可校验、可降级、可恢复（P0）

学习重点：保留结构化事实、限制摘要大小、摘要失败处理，以及上下文压缩的幂等性。

### 具体改动

- 建议新增 `core/context_compaction.py`，供自动压缩和手动压缩复用；`prompts/stage4.py` 负责模型摘要指令，结构化契约由代码验证。
- 事实层保留：任务和最新修正、计划、TODO ID/状态、验收标准、验证命令、关键文件、来源引用、最新失败与未完成项。
- 后台任务保留 `subagent_run_id`、任务目的、当前状态及已应用结果记录。压缩本身不取消、不重复派发后台任务。
- 最新结构化状态优先于旧摘要；明确区分已完成、失败、待执行和仅建议的内容，避免把建议当作执行结果。
- 模型只摘要历史发现与过程；不能自行改写验收标准或把 pending TODO 标成 completed。来源只保留可追溯引用，不能生成新的证据链接。
- 增加摘要 schema 和字段长度约束。关键字段缺失、JSON 无效或来源引用不合法时，用结构化状态补全或降级。
- 摘要模型自己的输入也要受预算约束：预先做有界抽取，必要时按完整消息组分块，再合并到目标摘要；每一步限制输入、输出和调用次数。
- 压缩后重新统计实际下一次请求，包括摘要、保留消息和工具 schema。目标是回到 target 水位；最多一次收紧处理，仍超限则返回明确失败。
- 任务、验收标准等不可丢弃内容本身超预算时，保留磁盘原件并报告哪些必需信息无法装入窗口，不静默裁掉需求。
- 模型不可用时生成确定性摘要，保留任务、验收、TODO、来源引用和当前错误；标明降级原因。
- 摘要和 checkpoint 按上下文版本写入，成功后再切换活动版本；失败保持旧版可恢复。旧消息清除需符合 LangGraph reducer 语义。
- 给 sources、handoffs、verification_checks、compression_events、历史摘要等记忆投影设置独立预算；磁盘可留全量，prompt 只带相关、有界内容和引用。

### 验收

- 多次压缩后，最新要求、未完成 TODO、验收标准、命令、关键来源和后台任务 ID 仍可恢复。
- 摘要失败、格式错误、超长摘要、必需内容超限均有确定结果，且不会无限递归压缩。
- 下一次实际请求使用新版本；压缩后恢复 checkpoint 不重复执行已完成工具。

## 6. 阶段四：在每轮模型调用前治理上下文（P0）

学习重点：真实请求与图状态的区别、模型工具循环、协议配对和执行边界。

### 具体改动

- 为请求准备建立共享入口，例如 `prepare_model_context`。调用方提供当前 messages、工具 schema、结构化状态和保留策略，返回本次实际发送的消息与预算快照。
- 在 planner/verifier 的每轮循环，以及 `agents/code_agent.py`、`agents/search_agent.py` 的每轮循环接入。路由、聊天和自定义 runner 同样必须经过受检的模型调用入口。
- 在 provider 调用边界增加最终预算校验，防止某个调用方漏接。超限时向外层返回可识别错误，由调用方处理，不盲目重试。
- 当前图状态的 messages 与节点局部 messages 并不相同。压缩必须作用于将被发送的局部列表，并把摘要及必要更新同步回图状态。
- 按“模型消息及其全部工具结果”划分消息组；整组保留或整组移入摘要，禁止留下悬空的 tool_call_id。
- 对每轮多工具结果设置共享预算。即使每个结果都满足阶段二限制，合并后仍需在下一次请求前检查。
- 保留最近必要消息，旧组进入压缩；不重跑已完成工具，也不通过修改工具预算绕过原有循环限制。
- 对后台子 Agent 使用独立消息与预算状态；父 Agent 回收结果后再次检查父级请求预算，不能让多个并发结果集中撑满输入。
- 保留图节点间 monitor，负责整体状态观察与兼容，不把它当成唯一防线。

### 验收

- 在单个 codeAgent/searchAgent 节点内制造多轮增长，压缩发生在下一次模型调用前。
- 多个工具调用的 ID 和结果仍匹配；压缩前后的写入操作执行次数保持一致。
- 覆盖同步/流式路径和无预算包装的漏接路径；最后的 provider 校验能拦截遗漏。

## 7. 阶段五：统一显式 compact 的行为（P1）

学习重点：持久会话与活动上下文的区别、请求接收与执行完成的区别、单一写入者。

### 交互定义

| 入口与状态 | 计划行为 |
| --- | --- |
| TUI 空闲时 `/compact` | 压缩保存的会话上下文，保留结构化任务信息与最近记录；报告 session 范围的前后估算量 |
| TUI 任务运行中 `/compact` 或独立快捷键 | 向当前 run 提交压缩请求，在下一个完整消息组边界应用；不打断正在执行的工具 |
| `mokioclaw compact --workspace ...` | 保持现有命令可用，压缩指定工作区保存的会话；明确报告生效范围 |
| 建议新增 `mokioclaw compact --run-id ...` | 通过 daemon 请求压缩活动 run，与 TUI 运行中操作保持一致 |

### 具体改动

- `core/session.py` 复用结构化保留契约，避免只取旧会话前 260 字符而丢失末尾的重要修正。
- `core/daemon.py`、`core/daemon_client.py` 增加压缩请求和状态查询；使用 request_id 标识 pending/applied/noop/failed 状态。
- daemon 只排入控制请求，由执行线程在边界应用，不从网络线程直接改写活动 messages。
- 当前 TUI 会在运行时禁用输入，需要单独保留控制入口，或允许控制命令并继续禁止提交新任务；耗时摘要运行在工作线程，不能阻塞 UI。
- 工作区存在活动写入者时，离线 session compact 应交给该写入者或返回明确冲突，避免任务结束保存旧 session 覆盖压缩结果。
- 合并同一上下文版本上的重复请求。自动压缩已满足手动请求时返回 noop 或关联已完成的压缩。
- 未知 run、已结束 run、daemon 停止、历史不足和取消请求等情况给出明确反馈。活动 run 的操作默认只作用于主执行上下文，后台子任务仍独立治理。
- 本地 Python 调用不依赖 daemon；通过同一上下文控制对象支持请求与回调。

### 验收

- 分别验证空闲 session、活动 run、短历史及重复命令。
- 显示“请求已接收”后，只有执行线程完成应用才出现“压缩完成”。
- 活动任务保存会话时不会覆盖已经完成的 session 压缩；不会把工作区 A 的请求应用到工作区 B。

## 8. 阶段六：补齐 TUI、CLI 与 trace 可观察性（P1）

学习重点：估算值、真实 usage、显示范围和事件生命周期的对应关系。

### 具体改动

- 预算事件统一携带：run/agent/scope、输入估算、窗口、输出预留、安全余量、水位、估算方法和请求序号。
- 裁剪事件携带：tool_call_id、裁剪原因、原始/保留大小及完整输出引用，不在事件摘要中重复展开完整内容。
- 压缩事件携带：request_id、自动/手动原因、作用范围、前后估算量、删除消息数、目标、上下文版本及降级/失败原因。
- TUI 展示当前输入估算与可用预算、最近一次压缩前后值；明确标注 estimated。session compact 和 run compact 分别标注，不能混用两者的 token 数。
- CLI 的手动命令返回前后值、保留记录数、状态和原因；自动事件与 TUI 使用相同字段。
- trace 汇总压缩次数、裁剪次数、压缩失败数、最大输入估算和估算方法。压缩前后比较采用相同算法和相同作用范围。
- 压缩失败保持可见，不能仍显示成功；重复渲染同一事件不重复累计指标。

### 验收

- Textual 测试实际检查组件内容和控制命令处理，不只检查格式化函数输出。
- 终端窄窗口仍可看到前后估算量和状态；详细内容可展开。
- CLI/TUI/trace 对同一请求的 request_id、上下文版本和前后值一致。

## 9. 实验与最终验收矩阵

每个阶段同时补对应测试。离线集成测试使用可控制的模型，并记录实际传入请求；真实模型实验单独执行并保留结果，两类证据不能互相替代。

| 用例 | 输入/操作 | 必须检查的结果 |
| --- | --- | --- |
| A 长文件 | 约 20 万字符、多行文件和单行超长文件；验收所需信息置于尾部 | 首次返回有界；提示补读位置；Agent 能补读并使用尾部信息 |
| B 大命令输出 | 10 万字符 stdout，末尾放入唯一错误标识；另测长 stderr | 头尾或后续读取能找到错误；完整日志存在；后续 prompt 不包含全量输出 |
| C 大结构化结果 | 1000 个短条目、深层字典、搜索结果、MCP 返回与长异常 | 最终序列化长度不超上限；JSON 有效；关键引用仍可用 |
| D 单节点多轮增长 | 在窗口能容纳必要规则的前提下调低预算；让 codeAgent 连续读取不同内容 | 节点内部触发压缩；每次实际请求满足预算；无 tool_call 配对错误 |
| E 手动压缩 | 空闲 `/compact`、运行中 compact 请求、CLI workspace/run 命令 | 作用范围正确；已接收与已完成可区分；新上下文用于下一次调用 |
| F 需求保留 | 把验收条件、来源 URL、TODO 和最新修正放在不同轮次，经历至少两次压缩 | 要求和来源引用保留；完成状态不被误改；最终通过预设验收脚本 |
| G 压缩故障 | 摘要模型失败、无效 JSON、超长摘要、计数失败、必要内容超限 | 有界降级或明确失败；旧上下文可恢复；不递归/无限重试 |
| H 后台与并发 | 两个后台检索返回大结果，同时请求主 run compact | 父/子预算独立；任务 ID 不丢；结果只应用一次；摘要版本不被旧结果覆盖 |
| I 恢复与连续运行 | 压缩后保存/恢复；接近既有循环上限反复产生工具结果；长会话重复 compact | 消息数量和请求大小受控；关键状态可恢复；已完成副作用不重放 |
| J 展示一致性 | 同一压缩事件送到 CLI、TUI 和 trace | 前后值、scope、原因和状态一致；无重复统计 |

真实模型验收采用一个离线可判定的产物任务，例如：读取长规格文件，按文件尾部要求创建报告，保留给定来源链接，运行独立脚本核验报告字段和来源。实验关闭无关网络检索，固定输入数据，记录模型、窗口配置、工具调用、压缩事件和最终脚本结果。

完成判据：至少一次自动压缩、一次手动会话压缩、一次活动任务手动压缩均产生可追踪事件；自动和活动压缩后任务通过独立验收，手动会话压缩后下一轮任务保留原要求并通过验收；全部请求通过调用前检查；全部工具结果满足总量限制；故障与并发用例通过。无法运行真实模型时必须标为“未验证”，不能用 mock 的 passed 替代。
